# 교실 탈출 구현 지시문

## 1. 작업 목표

초등학교 친구사랑 수업용 협동 방탈출 웹앱 **「교실 탈출」**의 첫 번째 에피소드 **「사라진 우정 열쇠」**를 구현하세요.

아래 요구사항을 기준으로 분석, 구현, 실행, 검증, 오류 수정까지 진행하세요. 계획만 작성하고 작업을 종료하지 마세요.

### 프로젝트 정보

- 제품명: 교실 탈출
- 에피소드: 사라진 우정 열쇠
- 대주제: 친구사랑
- 교육 목적: 듣기, 존중, 함께하기, 배려, 도움 요청 행동 연습
- 사용자: 초등학교 3~6학년 학생, 수업 교사, 학교 결과 운영자
- 참여 방식: 모둠별 태블릿 또는 PC 한 대
- 목표 플레이 시간: 20~25분
- 수업 구성: 도입 5분, 게임 25분, 되돌아보기 5분, 정리 5분
- 작업 유형: 신규 개발. 관련 구현이 이미 있으면 이어서 개발
- 저장소: 현재 작업 중인 이 프로젝트의 저장소
- 배포 환경: GitHub Pages
- 참고 사양: 이 프롬프트에 포함된 제품 요구사항과 퍼즐 데이터

저장소 주소와 배포 주소는 실제 작업 환경에서 확인하세요. 확인되지 않은 주소를 만들어 보고하지 마세요.

## 2. 작업 시작과 기존 코드 보존

1. 적용되는 AGENTS.md를 확인하세요.
2. 현재 저장소 상태와 사용자의 미커밋 변경을 확인하세요.
3. 기존 진입점, 실행 명령, 패키지 관리자, 프레임워크, 배포 설정을 확인하세요.
4. 관련 구현이 있으면 재사용하세요.
5. 사용자 변경과 관련 없는 기능을 보존하세요.
6. 변경할 파일, 구현 순서, 검증 방법을 간단히 정리하세요.
7. 정리 후 바로 구현을 진행하세요.

빈 프로젝트의 기본 기술은 TypeScript, Vite, CSS, DOM/SVG로 정하세요. 기존 프로젝트에 적합한 프레임워크가 있으면 그 구조를 유지하세요.

일반적인 색상, 여백, 컴포넌트 배치 등은 합리적으로 결정하세요. 실제 학교 목록이나 공식 회차 정보가 없더라도 연습 게임과 빈 순위 화면은 완성하세요.

개인정보 안내에서는 앱이 학생 개인정보를 입력받거나 전송하지 않는다는 점을 설명하세요. 호스팅 제공자의 접속 기록까지 없다고 보장하지 마세요.

## 4. 이야기와 게임 경험

친구사랑 축제의 마지막 활동으로 가상 교실 방탈출 챌린지가 시작됩니다.

학생들은 교실의 장치를 해결해 다섯 개의 우정 조각을 얻습니다. 조각을 연결하면 마지막 열쇠 위치가 드러납니다. 열쇠를 찾아 출구에 사용하면 탈출에 성공합니다.

가상 캐릭터는 토끼, 곰, 여우, 다람쥐로 구성하세요.

다음 상호작용을 실제로 구현하세요.

- 교실 물건 조사
- 단서 수집과 다시 읽기
- 가방에서 도구 선택 및 적용
- 카드 뒤집기와 순서 배치
- 투명판 회전과 정렬
- 화살표 경로 설계
- 연결 스위치 조작
- 지도 이동과 문장 조합
- 우정 조각 배치와 회전
- 마지막 열쇠 획득 및 출구 사용

실제 교실 문을 잠그는 활동은 포함하지 마세요.

학생에게 실제 피해 경험을 발표하도록 요구하지 마세요. 사과, 용서, 특정 친구와 친해지기를 게임 완료 조건으로 요구하지 마세요.

점수는 퍼즐 해결 기록입니다. 학생 인성이나 학교폭력 발생 수준을 평가하는 지표로 표현하지 마세요.

## 5. 화면과 교실 구성

### 화면 8개

1. 시작 화면
   - 제목, 새 게임, 이어하기, 수업 안내, 공식 학교 순위
   - 유효한 저장 기록이 없으면 이어하기 비활성화

2. 학교·활동 설정
   - 등록 학교 검색 및 선택
   - 학교 없이 체험
   - 소리 설정
   - 학교 자유 입력 기능 없음

3. 이야기·조작 안내
   - 짧은 이야기
   - 조사하기, 아이템 사용하기, 힌트 안내
   - 시작 전 타이머 정지

4. 교실 탐색
   - 교실 장면, 조사 패널, 퍼즐
   - 가방, 단서 노트, 점수, 조각 수
   - 힌트와 일시정지

5. 탈출·성찰
   - 확정 점수, 완료 퍼즐, 추가 단서
   - 기기 내 활동 시간
   - 실천 문장 선택
   - 조건에 맞는 결과 내보내기와 인쇄

6. 공식 학교 순위
   - 회차, 학교명, 점수, 공동 순위, 게시본 갱신일
   - 기기 내 점수와 공식 순위를 명확히 구분

7. 교사용 안내
   - 40분 수업 운영
   - 모둠 역할과 힌트 활용
   - 저장 범위와 개인정보 안내

8. 결과 파일 집계
   - 로컬 JSON 파일 선택
   - 검증, 중복·충돌 처리
   - 새 순위 파일 다운로드
   - 원격 쓰기 권한 없음

해시 경로를 사용하세요. 예시는 `#/play`, `#/result`, `#/rankings`, `#/tools/results`입니다.

### P1. 게시판의 반쪽 메모

교육 주제: 듣기.

카드 데이터:

- P1-C3: “함께 만들고 싶어. 만드는 방법을 먼저 알려 주면 좋겠어.” 토끼의 직접 발언. O03에서 발견.
- P1-C4: “토끼는 만드는 방법을 이미 알고 있을 거야.” 다른 친구의 추측. O02에서 발견.
- P1-C5: 토끼가 안내 그림을 가리키는 그림. O02에서 발견.

조사한 카드를 단서 노트에 보관하세요.

카드를 뒤집어 지도 조각을 확인하게 하세요. 다음 연결 기호를 표시하세요.

- C3: 왼쪽 반원, 오른쪽 삼각형
- C5: 왼쪽 삼각형, 끝 표시
- C2·C4: 정답 조각과 맞지 않는 사각 연결

성공 조건:

- 필요한 카드 세 장을 발견했음.
- 배치 순서가 C1 → C3 → C5임.

완성된 지도는 O04를 가리키게 하세요.

추측 카드를 사용하면 토끼가 직접 전한 이야기를 더 찾아보도록 안내하세요.

### P3. 모두에게 닿는 우정 공

교육 주제: 함께하기.

5×5 화살표 놀이판을 구현하세요.

좌표:

- 시작: (1,3)
- 골대: (5,3)
- 벽: (2,2), (4,2), (2,4), (4,4)
- 토끼: (1,1)
- 여우: (3,1)
- 곰: (3,5)
- 다람쥐: (5,5)

네 캐릭터는 모두 공놀이에 참여하고 싶다고 말하게 하세요.

벽과 골대를 제외한 칸에 화살표를 배치하세요. 초기 방향은 모두 오른쪽으로 하세요. 한 번 누르면 시계 방향으로 90도 회전하게 하세요.

실행하면 공이 현재 칸의 화살표를 따라 한 칸씩 이동하게 하세요.

검증용 성공 경로:

```text
(1,3) → (1,2) → (1,1) → (2,1) → (3,1)
→ (3,2) → (3,3) → (3,4) → (3,5)
→ (4,5) → (5,5) → (5,4) → (5,3)
```

성공 판정:

- 네 캐릭터를 모두 방문
- 벽 충돌 없음
- 범위 이탈 없음
- 같은 칸 재방문 없음
- 골대 도착

방문 집합과 종료 상태를 검사하세요. 특정 경로 문자열과 같은지만 비교하지 마세요.

반복 경로와 최대 이동 수를 검사해 무한 실행을 막으세요.

실패 후에도 타일 방향을 유지하세요. 공을 받지 못한 캐릭터나 실패 위치를 표시하세요.

보상:

- F3 함께하기 조각
- 16점
- O08 태블릿 활성화

### P4. 사진과 도움의 두 연결망

교육 주제: 배려.

노드:

- S: 가상 친구의 기기
- G: 단체 대화방
- X: 다른 대화방
- H: 함께 돕는 친구
- T: 교무실 선생님
- C: 상담교사

연결과 초기 상태:

- photo-1: S → G, ON
- photo-2: G → X, ON
- help-1: S → H, OFF
- help-2: H → T, OFF
- help-3: H → C, OFF

사진과 도움 요청은 별도 상태로 관리하세요. 아이콘과 글자로 정보 종류를 구분하세요.

성공 조건:

```text
photo-1 = OFF
AND photo-2 = OFF
AND help-1 = ON
AND (help-2 = ON OR help-3 = ON)
```

교무실만 연결, 상담교사만 연결, 둘 다 연결하는 세 상태를 모두 정답으로 인정하세요.

사진 전달을 차단했지만 도움 경로도 끊긴 상태는 성공으로 처리하지 마세요.

이미 전달된 사진이 자동 삭제된 것처럼 연출하지 마세요.

보상:

- F4 배려 조각
- 16점
- O09 도움 지도 활성화

### P5. 도움이 닿는 지도

교육 주제: 도움.

지도 연결:

- 교실 ↔ 복도
- 복도 ↔ 담임 자리
- 복도 ↔ 교무실
- 복도 ↔ 상담실

장소 상태:

- 담임 자리: 지금 자리에 없음
- 교무실: 도움 가능한 선생님 있음
- 상담실: 도움 가능한 상담교사 있음

교무실 또는 상담실에 도착하면 도움 요청 문장을 조합하게 하세요.

문장 카드:

- R0: “도움이 필요한 일이 있어요.”
- R1: “따로 이야기하고 싶어요.”
- R2: “친구와 함께 이야기해도 될까요?”

성공 조건:

- 도움 가능한 장소 도착
- R0를 먼저 배치
- R1 또는 R2를 하나 이상 연결

R1과 R2를 모두 선택하면 두 카드 사이의 순서는 제한하지 마세요.

담임 자리 방문은 필수 조건이 아닙니다. 부재 장소에서 돌아가도 감점하지 마세요.

보상:

- F5 도움 조각
- 16점
- 마지막 조합판 활성화

### 마지막 조합과 출구

조각 순서:

```text
F1 듣기 → F2 존중 → F3 함께하기 → F4 배려 → F5 도움
```

같은 순서를 칠판에도 표시하세요.

초기 회전:

- F1: 90도
- F2: 180도
- F3: 270도
- F4: 90도
- F5: 180도

올바른 순서로 배치하고 모두 0도로 맞추면 지도가 완성되게 하세요.

완성 문구:

```text
창가 / 둥근 / 화분 / 받침 / 아래
```

이후 진행:

1. 최종 조합 완료
2. O11 화분 받침 조사
3. `final-key` 획득
4. 가방에서 열쇠 선택
5. O12 출구에 사용
6. 탈출 완료

최종 조합 전에는 화분을 조사해도 열쇠를 얻을 수 없게 하세요.

다섯 조각 보유, 100점 획득, 최종 조합 완료만으로 자동 탈출시키지 마세요.

## 7. 추가 단서와 점수

### 추가 단서

- B1: 책장 그림 비교
  - 왼쪽: 삼각형·하트·별
  - 오른쪽: 원·나뭇잎·하트
  - 정답: 공통 기호 하트

  - 정답: 펼친 두 손과 ‘함께 쓰기’
  - 다른 보기: 개인용 자물쇠, 사용 중 시계

- B3: 게시판 초대장 조합
  - 1: “놀이 방법을 알려 줄게”
  - 2: “함께하고 싶으면 말해 줘”
  - 3: “지금은 쉬어도 괜찮아”
  - 정답 순서: 1 → 2 → 3
  - 1과 2는 원, 2와 3은 삼각형 맞물림으로 연결

- B4: 출구 옆 기호 암호
  - P5 완료 후 활성화
  - 기호 순서: 화살표 → 말풍선 → 어른
  - 지도 범례: 화살표=3, 말풍선=1, 어른=2
  - 정답: 312

B1~B3는 탐색 시작부터 사용할 수 있게 하세요. 작은 픽셀을 우연히 눌러야 발견하는 방식은 사용하지 마세요.

### 점수 계산

```text
score = 완료한 필수 퍼즐 수 × 16
      + 발견한 추가 단서 수 × 5
```

- 필수 퍼즐: P1~P5, 총 80점
- 추가 단서: B1~B4, 총 20점
- 총점: 100점
- 최종 조합과 열쇠 사용: 별도 점수 없음

점수는 허용된 완료 ID에서 계산하세요. 이벤트마다 숫자를 계속 더하는 방식은 사용하지 마세요.

정상 게임 상태에서 완료 ID를 중복 없이 관리하세요. 저장 데이터와 가져온 파일의 중복 ID는 검증 오류로 처리하세요.

출구를 열기 전에 남은 추가 단서 수를 안내하세요. ‘계속 탐색하기’와 ‘탈출하기’를 제공하세요.

탈출 후 점수를 고정하세요.

### 힌트와 시간

각 필수 퍼즐과 최종 조합에 힌트 3단계를 제공하세요.

1. 살펴볼 위치
2. 연결할 단서와 해결 원리
3. 실제 해결 방법

P3의 마지막 힌트에는 정답 경로를 보여 주세요. 적용 버튼을 제공한다면 화살표만 설정하고 실행과 성공 판정은 정상 절차를 따르게 하세요.

힌트 사용과 플레이 시간은 점수 및 동점 순위에 영향을 주지 않게 하세요.

타이머는 실제 플레이 중에만 증가하게 하세요. 안내, 일시정지, 탭 비활성화, 결과 화면에서는 정지시키세요.

시간이 지나도 강제 실패 처리하지 마세요.

## 9. 공식 회차 설정

`public/data/game-config.json`을 현재 회차·에피소드·난이도·콘텐츠 버전의 기준으로 사용하세요.

초기 데이터:

```json
{
  "schemaVersion": 1,
  "episodeId": "ep01",
  "difficultyId": "standard",
  "contentVersion": "ep01-1.0.0",
  "activeRound": null
}
```

`activeRound: null`이면 연습 모드입니다.

공식 회차를 열면 다음 필드를 가진 객체를 사용하세요.

- roundId: 비어 있지 않은 문자열
- label: 회차 이름
- acceptingResults: 불리언

새 게임 시작 시 비교 조건을 진행 기록에 복사해 고정하세요. 접수 중인 회차가 없으면 진행 기록의 `roundId`를 null로 저장하세요.

공식 결과 내보내기는 다음 조건을 모두 만족할 때만 허용하세요.

1. 등록 학교 선택
2. 탈출 완료
3. 유효한 현재 설정
4. 접수 중인 공식 회차
5. 저장된 회차·에피소드·난이도·콘텐츠 버전이 현재 설정과 일치

설정은 시작, 이어하기, 공식 내보내기 시 읽고 검증하세요.

설정 읽기에 실패하면 게임은 연습으로 진행할 수 있게 하세요. 공식 결과 내보내기는 비활성화하세요.

이전 회차 기록은 호환되는 콘텐츠에서 연습으로 이어갈 수 있게 하세요. 이전 기록의 회차를 새 회차로 바꾸지 마세요.

현재 회차에 참가하려면 새 게임을 시작하게 하세요.

## 10. 학교 경쟁과 결과 집계

### 운영 방식

학교별 공식 결과 한 건을 운영자가 확인한 뒤 순위에 반영하세요.

기본 운영 규칙은 공식 도전 전에 학교 대표 모둠을 정하고 그 모둠의 완료 결과를 제출하는 방식입니다. 교사용 안내에 이 규칙을 설명하세요.

학생 수, 접속 수, 참여 모둠 수로 점수를 늘리지 마세요.

공식 결과 처리 흐름:

1. 게임 탈출 완료
2. 조건을 충족한 결과 JSON 다운로드
3. 학교 담당자의 공식 결과 확인
4. 운영자에게 수동 전달
5. 운영자가 로컬 집계 화면에서 파일 선택
6. 검증과 중복·충돌 처리
7. 새 rankings.json 다운로드
8. 운영자가 저장소의 정적 파일을 교체해 배포

집계 화면에 GitHub 쓰기 기능이나 서버 전송 기능을 넣지 마세요.

결과 다운로드 후 다음 문구를 표시하세요.

“결과 파일을 저장했어요. 공식 순위 반영은 운영자 확인 후 이루어져요.”

### 학교 목록과 순위

등록 학교만 `schools.json`에 넣으세요.

실제 학교 목록이 제공되지 않았다면 빈 배열로 시작하세요. 학교 ID를 공식 교육행정기관 코드라고 주장하지 마세요.

점수 내림차순으로 정렬하세요.

동점은 공동 순위로 표시하세요.

```text
100점, 95점, 95점, 90점
→ 1위, 2위, 2위, 4위
```

동점 학교의 이름순 정렬은 화면 배치에만 사용하세요.

공식 데이터가 없으면 빈 상태를 표시하세요. 예시 학교와 예시 점수를 실제 순위에 섞지 마세요.

개발용 데이터는 테스트 fixture로 분리하세요.

### 결과 파일

허용 구조:

```json
{
  "schemaVersion": 1,
  "recordType": "classroom-escape-result",
  "episodeId": "ep01",
  "roundId": "round-01",
  "difficultyId": "standard",
  "contentVersion": "ep01-1.0.0",
  "schoolId": "SCHOOL001",
  "solvedPuzzleIds": ["P1", "P2", "P3", "P4", "P5"],
  "foundBonusIds": ["B1", "B3"],
  "escaped": true
}
```

위 학교와 회차는 구조 설명용 예시입니다. 운영 데이터로 등록하지 마세요.

점수는 완료 ID에서 재계산하세요. 위 예시는 90점입니다.

결과 파일과 파일명에 개인 정보, 개인별 활동 시각, 기기 식별자, 성찰 답변, 힌트 이력을 넣지 마세요.

### 공개 순위 파일

초기 구조:

```json
{
  "schemaVersion": 1,
  "episodeId": "ep01",
  "roundId": null,
  "difficultyId": "standard",
  "contentVersion": "ep01-1.0.0",
  "updatedAt": null,
  "records": []
}
```

공식 회차가 열리면 실제 회차 ID를 사용하세요.

각 순위 행에는 다음 필드만 허용하세요.

- schoolId
- score
- bonusCount
- escaped

행 검증 조건:

- 등록 학교 ID
- 같은 회차 내 학교 ID 중복 없음
- bonusCount: 0~4의 정수
- score: `80 + 5 × bonusCount`와 일치하는 정수
- escaped: true

`roundId`가 null이면 records는 빈 배열이어야 합니다.

`updatedAt`은 게시본 생성 시각입니다. 학생별 기록 시각을 공개하지 마세요.

### 파일 검증과 충돌

결과 파일과 순위 파일에 별도 스키마를 적용하세요.

결과 파일:

- P1~P5를 각각 정확히 한 번 포함
- 보너스는 B1~B4의 중복 없는 부분집합
- 등록 학교
- 탈출 완료
- 허용 필드만 포함

기존 순위 파일:

- 공개 순위 스키마로 검사
- 보너스 개수 범위 검사
- 점수 일치 검사
- 학교 중복 검사
- 존재하지 않는 퍼즐 ID 필드를 요구하지 않음

두 파일 모두 회차·에피소드·난이도·콘텐츠 버전을 검사하세요.

파일 하나는 100KB 이하로 제한하세요. 한 번에 최대 100개를 읽게 하세요.

완전히 같은 결과는 한 건으로 유지하세요. 같은 학교·회차의 다른 결과는 기존 유지 또는 새 결과 교체를 선택하게 하세요.

잘못된 파일은 반영하지 않고 오류 이유를 표시하세요. 알 수 없는 필드는 거부하세요.

파일 형식 검사가 실제 플레이를 증명하지 않는다는 점을 운영자 안내에 설명하세요.

현재 회차 집계에는 유효한 설정과 접수 중인 회차가 필요합니다. 지난 회차 자료를 현재 회차로 자동 합치지 마세요.

종료된 회차의 마지막 순위는 해당 회차와 종료 상태를 표시해 조회할 수 있게 하세요.

```text
src/game/

src/content/
src/storage/
src/ranking/
src/tools/
src/ui/
public/assets/
public/data/
tests/
```

폴더 구조를 맞추기 위해 기존 코드를 불필요하게 전면 교체하지 마세요.

GitHub Pages 프로젝트 하위 경로를 지원하세요.

- 실제 저장소 이름에 맞는 base 설정
- base를 반영한 이미지·음향·JSON 경로
- 해시 라우팅
- 하위 경로에서 직접 접근과 새로고침 확인
- 도메인 루트의 /assets/ 또는 /data/ 경로를 가정하지 않기

초기 로딩에 필요한 자산과 게임 데이터를 확인한 뒤 시작하게 하세요. 필수 자산을 읽지 못하면 재시도 경로를 제공하세요.

첫 버전은 온라인 최초 접속을 기준으로 구현하세요. 완전한 오프라인 시작과 서비스 워커는 후속 범위로 두세요.

성능 목표:

- 초기 핵심 자산 합계 4MB 이내
- 초기 JS·CSS gzip 합계 400KB 이내

실제 측정값과 목표값을 구분해 보고하세요.

## 14. 완료 기준과 검증

다음 36개 항목을 통과·실패·미실행으로 기록하세요.

- AC01: 학교 없이 개인정보 입력 없이 게임 시작.
- AC02: 선택한 등록 학교가 진행 기록에 유지됨.
- AC03: P1 정답 연결 시 F1과 16점을 한 번만 획득.
- AC04: 개인 도구를 빌릴 수 없어도 공용 도구로 진행 가능.
- AC05: P2 도구 적용·정렬·713 입력 조건을 함께 검사.
- AC06: P3에서 네 캐릭터를 모두 지나 골대 도착 시 성공.
- AC07: P3의 캐릭터 누락·벽·반복·범위 이탈을 실패 처리.
- AC08: P4 사진 차단만 하고 도움 경로가 없으면 실패.
- AC09: P4의 세 가지 유효한 도움 연결을 모두 성공 처리.
- AC10: P5에서 부재 장소 이후 대체 경로로 진행 가능. 바로 도움 가능한 장소로 가도 성공.
- AC11: 같은 퍼즐 정답을 반복해도 점수와 조각 수 증가 없음.
- AC12: 같은 보너스를 반복 조사해도 5점만 반영.
- AC13: 필수 퍼즐 완료 시 80점이며 아직 탈출 완료가 아님.
- AC14: 100점이어도 출구를 열기 전에는 공식 완료 파일 내보내기 불가.
- AC15: 최종 조합·화분 조사·열쇠 획득·출구 사용 후 탈출 완료.
- AC16: 탈출 후 추가 조작으로 확정 점수가 바뀌지 않음.
- AC17: 새로고침 후 진행 복원. 일시정지 상태로 이어하기.
- AC18: 로컬 저장 불가 상태에서도 현재 게임 진행 가능.
- AC19: 활동 지우기가 이 앱의 저장 키만 삭제.
- AC20: 잘못된 버전·중복 ID·추가 개인정보 필드가 있는 파일 거부.
- AC21: P1~P5와 B1·B3 결과를 90점으로 재계산.
- AC22: 동일 학교·회차의 다른 결과에 충돌 선택 제공.
- AC23: 100·95·95·90점이 1·2·2·4위로 표시.
- AC24: 공식 기록이 없으면 빈 상태 표시. 가짜 순위 생성 없음.
- AC25: 학교·순위 읽기 실패 시 체험 게임 유지.
- AC26: 스마트폰 360px·태블릿·PC에서 필수 정보와 조작 대상에 접근 가능.
- AC27: 키보드로 전체 필수 조작과 패널 닫기 가능.
- AC28: 소리 끄기·움직임 줄이기 상태에서 모든 단서 확인 가능.
- AC29: 실제 프로젝트 하위 경로에서 자산·JSON·화면 새로고침 정상.
- AC30: 외부 수집·추적 요청과 학생 개인정보 필드 없음.
- AC31: 선행 퍼즐 없이 다음 장치에 접근해도 해금 조건 유지.
