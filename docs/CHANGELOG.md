# 변경 기록

버전별 변경 내용과 당시의 검증 범위를 최신순으로 모았습니다. 운영·수업·자산 안내는 [OPERATIONS.md](OPERATIONS.md), [TEACHER.md](TEACHER.md), [ASSETS.md](ASSETS.md), 3D 구조는 [3D-CLASSROOM.md](3D-CLASSROOM.md)를 참고하세요.

## 1.7.1 · 다듬기

- 휴대폰에서 버튼을 누를 때 구글 '탭하여 검색' 창이 뜨지 않고, 전체화면의 3D 칠판 글씨가 선명해졌습니다.
- 도서관·체육관의 화면, 힌트, 단서 노트, 인쇄 자료에 남아 있던 교실 문구를 모두 바꿨습니다.
- 「다시 해도 다른 암호·카드」를 켜고 수업 전에 인쇄한 역할 카드가 다음 새 게임과 같은 숫자를 씁니다.
- 글 읽어 주기가 다른 화면으로 가면 멈추고, 인쇄 자료의 수업 흐름이 고른 수업 시간을 따릅니다.
- 브라우저 자동 검사가 세 에피소드의 인쇄 자료와 미리 인쇄한 역할 카드까지 확인합니다.
- 활동 설정에 **쉬운 말로 보기**를 추가했습니다. 어려운 낱말을 쉬운 말로 바꾸고 물건마다 지금 할 일을 한 줄로 보여 줍니다.

## 1.7.0 · 함께 읽고 넓히기

- 도서관·체육관 에피소드에 각자의 그림 모드 그림을 넣었습니다. 물건 위치는 교실과 같습니다.
- 활동 설정에 **글 읽어 주기**를 추가했습니다. 켜면 조사 화면과 대화창에서 안내 문장을 한국어 음성으로 읽습니다.
- 학교 목록에서 빠진 학교의 이어하기 기록은 지우지 않고 연습 모드로 이어 갑니다.
- 브라우저 자동 검사가 도서관·체육관 에피소드와 기본 쉬운 모드까지 확인합니다.

## 1.6.1 · 차분한 화면 전환

- 새 게임은 `움직임 줄이기`를 켠 상태로 준비합니다. 기존 저장 게임의 명시적인 설정은 유지하며 활동 설정에서 바꿀 수 있습니다.
- 물건이나 탐색 지도 항목을 누르면 카메라 이동·회전을 먼저 재생하지 않고 조사 화면을 바로 엽니다. 실제 도착 장소와 지도 위치는 해당 물건으로 갱신하고, 돌아왔을 때 보는 방향은 유지합니다.
- 일시정지를 풀거나 이어하기에서 탐색을 재개할 때 전체화면을 강제로 다시 켜지 않습니다. 시작과 사용자의 전체화면 버튼은 기존 방식으로 동작합니다.
- 같은 크기의 같은 메모 화면에서는 메모판 높이를 유지해 선택 카드가 바뀌어도 스크롤이 갑자기 당겨지지 않게 합니다. 화면 크기나 물건이 바뀌면 새 크기로 배치합니다.
- 메모를 고른 뒤에는 다음 카드로 키보드 초점을 넘깁니다. 대화·힌트·길 확인은 필요한 만큼만 스크롤하며, 화면 가운데나 맨 위로 크게 이동시키지 않습니다.

색상·글꼴·조작·퍼즐 규칙과 점수, 기존 저장 키를 유지합니다. 검증은 브라우저 가로 화면의 물건 선택·지도·일시정지·이어하기·메모 및 전체 진행으로 수행하고, 실기기 검증은 제외합니다. 공개 배포의 워크플로·자산 해시·UI 확인 결과는 별도 증거 폴더에 남깁니다.

## 1.6.0 · 편하게 읽고 플레이하기

### 네 가지 개선

- **3D 화질:** 큰 칠판·게시판의 글씨 텍스처를 가로·세로 각각 두 배로 그립니다. 한글 글꼴 준비 후 생성하며, 비스듬한 면의 필터링을 보강합니다. 렌더링 상한은 모바일 100만 픽셀/1.5배, 데스크톱 300만 픽셀/2배로 제한합니다. 기존 모바일 30fps 제한·그림자 생략·정지 화면의 낮은 갱신 빈도는 유지합니다. 실제 기기 프레임 성능을 측정한 수치는 아닙니다.
- **갑자기 작아지던 조사 화면:** 물건을 선택해도 전체 플레이 너비를 사용합니다. 조사 카드의 고정 760px 제한을 제거하고, 짧은 안내도 남는 화면을 채웁니다. 퍼즐은 기존처럼 한 페이지에서 스크롤하며 전체화면의 소유자는 계속 `#app`입니다.
- **글 상자 여백:** 메모 카드의 패딩을 0으로 덮어쓰던 규칙을 수정했습니다. 본문·제목·기호·놓기 안내를 각 줄에 배치하고, 카드 안쪽 여백은 휴대폰 18px·넓은 화면 22px를 사용합니다. 긴 글은 줄바꿈하며 선택 불가 상태에서도 내용을 읽을 수 있습니다. 안내문·대화 상자의 여백과 줄 간격도 넓힙니다.
- **쉬운 기본 난이도:** 새 방문자의 새 게임은 `쉬움 · 차근차근`이며 추가 역할 암호는 기본으로 끕니다. 메모는 첫 장을 놓고 다음 한 장씩 고르게 합니다. 렌즈 방향은 자동으로 맞춥니다. 길 만들기는 다음 친구까지 이어 주는 선택 도움 버튼을 제공합니다. 교실·도서관의 도움 요청은 사진 멈추기→어른에게 도움 요청하기 두 단계로, 체육관은 두 팀 계획 중 선택으로 단순화합니다. 기존 `기본 · 스스로` 난이도는 새 게임 수업 설정에서 선택할 수 있습니다.

### 기존 진행에서 쉽게 바꾸기

메뉴→활동 설정→`쉬운 난이도로 바꾸기`를 누릅니다. 찾은 단서·도구·완료 퍼즐·점수는 유지합니다. 풀지 못한 메모의 잘못된 순서는 첫 장부터 다시 돕고, 풀지 못한 렌즈는 정렬합니다. 쉬운 활동은 연습 모드로 이어가며 공식 회차에는 제출하지 않습니다. 저장·재접속에도 같은 쉬운 설정을 유지합니다. 이미 탈출한 결과는 바꾸지 않습니다.

### 실행 검증

- 568×320 브라우저 가로 화면에서 세 에피소드 모두 쉬운 메모→렌즈→길 만들기 도움→도움 요청/팀 계획→선생님 대화→다섯 조각→열쇠→출구를 거쳐 80점 탈출했습니다.
- 교실 대화 중간에 저장·새로고침·이어하기로 같은 대화를 마쳤습니다. 기존 16점 활동의 난이도를 바꿔 점수가 유지되는 것도 확인했습니다.
- 새 로컬 출처의 첫 방문에서 쉬움 선택과 역할 암호 끄기가 기본임을 확인했습니다. 기본 난이도로 바꾸면 기존 선택 카드·연결망·세 팀 계획을 유지합니다.
- 휴대폰 메모 카드의 실제 패딩 18px·flex 줄 배치·내부 글자 잘림 없음, 넓은 화면 기본 난이도의 오답 카드에서도 패딩 22px와 줄바꿈을 확인했습니다.
- 고른 메모 칸의 고정을 해제해 스크롤 중 남은 카드 제목을 덮지 않도록 했습니다.
- 1114×622에서 조사 화면의 주 영역 너비 1099px(스크롤바 제외), 조사 카드 약 1019px를 확인했습니다. 돌아오면 3D 캔버스가 1114×622로 채워집니다. 전체화면 탐색·조사 화면도 같은 뷰포트 너비를 사용했습니다.

단위·회귀 검사, Pages 경로 빌드, 오프라인 자산 검사, 용량 검사를 수행합니다. 공개 Pages의 배포·자산 해시·후속 UI 검증은 별도 증거 폴더에 기록합니다. 실기기 터치·주소창·노치·모바일 운영체제 전체화면 검증은 제외합니다.

## 1.5.1 · 세 에피소드 탐색 지도 점검

기존 색상·글꼴·버튼 크기·지도 배치는 유지했습니다. 실기기 검증은 제외합니다.

### 수정 내용

- 이미 살펴본 물건이 다음 목표일 때 `★ 다음 물건 · ✓ 살펴봄`을 함께 표시합니다. 쪽지를 찾은 뒤 게시판으로 돌아갈 때, 살펴본 도구함이 다음 목표가 될 때 방문 표시가 사라지던 문제를 수정했습니다.
- 지도 그림의 물건 설명과 아래 선택 버튼이 같은 목표·방문 상태를 사용합니다. 목적지를 지나가기만 해서는 방문 표시를 붙이지 않고, 물건 조사 화면을 열었을 때 표시합니다.
- 일반 이동 중 각 통로에 도달할 때 실제 위치 이름과 저장 위치를 즉시 갱신합니다. 지도를 열거나 일시정지해 이동이 중단되면 마지막으로 도달한 안전한 통로를 표시하고, 이어하기에서도 같은 위치를 복원합니다.
- 기존 진행 저장 형식·점수·퍼즐 규칙을 유지합니다.

### 로컬 브라우저 검증

- 568×320 가로 화면에서 교실·도서관·체육관의 물건 12개씩을 탐색 지도에서 직접 선택했습니다. 물건 조사 후 실제 공간의 장소 이름·지도 위치 이름·표시점 좌표를 비교했습니다.
- 새 게임에서는 방문 표시가 없고 게시판만 다음 목표입니다. 게시판 조사→쪽지 발견→메모 해결에 따라 다음 목표가 쪽지→게시판→도구함으로 바뀌고, 이미 조사한 물건의 방문 표시가 유지되는 것을 확인했습니다.
- 세 에피소드 모두 창가·뒤편에서 저장→시작 화면→새로고침→이어하기 후 현재 위치·다음 목표·방문한 12개 물건을 확인했습니다.
- 체육관에서는 움직임 줄이기를 끈 상태로 뒤편에서 창가로 이동했습니다. 중간 통로에 도착한 뒤 지도를 열어 이동을 중단하고, 지도와 실제 장소가 일치하는 것과 저장·새로고침·이어하기 복원을 확인했습니다.
- 지도 목록의 가로 넘침과 버튼 내부 글자 잘림이 없고, 목록을 스크롤해 물건을 선택할 수 있음을 확인했습니다.

단위·회귀 검사는 `npm test`, Pages 경로 빌드는 `PAGES_BASE=/Escape-Class/ npm run build`, 오프라인 파일 검사는 `npm run test:offline`, 용량 검사는 `npm run measure`로 수행합니다. 공개 배포의 워크플로·자산 해시·세 에피소드 재검증 결과는 별도 증거 폴더에 저장합니다. 브라우저 가로 화면 검증을 실기기 터치·주소창·노치·모바일 운영체제 검증으로 간주하지 않습니다.

## 1.5.0 · 고도화 10가지

기존 색상·글꼴·방탈출의 기본 조작을 유지합니다. 학생의 필수 진행에는 기존 목표와 네 가지 탐색 도구를 사용하고, 연습과 교사용 도구는 선택 화면에 둡니다.

- 스크롤한 이전 글이 제목줄 위 여백으로 비치지 않도록 고정 제목 배경을 여백까지 확장했습니다.

## 1.4.8 · 가로 화면 알림·스크롤 가림 수정

기존 배포판의 568×320 가로 화면에서 암호를 틀리면 고정 알림이 입력한 숫자를 덮었습니다. 대화상자 밖의 알림은 네이티브 dialog의 최상위 레이어 뒤에 숨을 수 있었습니다.

### 변경

- 스마트폰 가로 화면의 퍼즐 안내는 고정 제목줄 안에서 줄바꿈해 표시합니다. 입력 숫자 위의 떠 있는 알림을 제거했습니다.
- 협동 암호 결과는 키패드 옆 단서 안내 자리에서 표시합니다. 다른 대화상자도 내부에 결과 안내 자리를 둡니다.
- 제목이 줄바꿈되거나 알림·전체화면·화면 크기 변경으로 높이가 달라지면 실제 제목줄 높이를 측정해 스크롤 여백을 갱신합니다. 제목줄 여백과 버튼 여백이 중복되던 부분을 줄였습니다.
- 알림이 나타나고 사라질 때 자동 스크롤 보정으로 읽던 위치가 움직이지 않도록 했습니다. 관찰자는 화면을 다시 그릴 때 해제합니다.
- 색상, 글꼴, 교실 그래픽, 퍼즐 규칙, 점수와 저장 형식은 유지합니다.

### 로컬 검증

- 기존 자동 검사 87개, TypeScript 및 실제 Pages 경로 빌드 통과.
- 브라우저의 568×320 가로 화면으로 새 게임부터 협동 암호, 다섯 필수 퍼즐, 조각 조합, 화분, 열쇠 사용을 거쳐 80점 탈출 완료. 콘솔 오류 없음.
- 오답 안내와 입력 숫자가 겹치지 않음. 긴 단서 노트 끝에서도 제목과 48×48 닫기 버튼 노출. 노트 가로 넘침 없음.
- 알림이 있는 퍼즐 제목줄 높이 109px에 따라 스크롤 여백이 117px로 갱신됨. 노트 제목줄 56px에 대한 여백 78px 적용.
- 667×375로 변경한 뒤에도 진행 상태와 탈출 동작 유지.

실기기와 모바일 브라우저의 주소창·노치·운영체제 전체화면은 이번 검증에서 제외합니다. 전체화면 상태 전이는 자동 검사와 데스크톱 브라우저 조작으로 확인하며, 모바일 네이티브 동작 통과로 간주하지 않습니다.

## 1.4.7 · 스마트폰 가로 화면 읽기·조작 개선

기존 색상·글꼴·교실 공간·퍼즐·점수·저장 형식을 유지하고 가로 화면 전용 스타일을 추가했다. 실기기 시험은 사용자 요청에 따라 제외한다.

### 확인한 문제와 수정

- 568×320 배포본에서 메모 내용 15px, 빈칸 표시 11px, 하단 버튼 14px였다. 본문·제목 18px, 빈칸 14px, 하단 버튼 16px로 키웠다. 3D 물건 이름은 17px, 도크 버튼 17px로 키웠다.
- 퍼즐을 오래 읽은 뒤 교실로 돌아가려면 페이지 위나 아래로 이동해야 했다. 교실 복귀와 현재 장치 이름을 상단에 유지한다.
- 기기 카드 내부가 아닌 페이지 전체가 스크롤되는데 스크롤 안내가 카드 높이만 검사했다. 실제 스크롤 영역을 감지하고 아래 내용·위로 돌아보기 안내를 갱신한다. 갱신 전 리스너와 ResizeObserver를 정리한다.
- 메모 빈칸과 렌즈 숫자 줄이 작은 화면을 가리지 않도록 일반 흐름에 놓았다. 메모 제목·내용·연결 기호는 구분된 줄로 표시한다. 퍼즐 내부에 이중 스크롤을 만들지 않는다.
- 대화상자 제목과 닫기를 함께 고정하여 긴 단서 노트에서도 접근할 수 있다. 배경 페이지로 스크롤이 이어지지 않도록 overscroll을 제한한다.
- 협동 암호 단계는 설명·입력값·단서 다시 보기를 왼쪽, 숫자판을 오른쪽에 놓는다. 568×320에서 11개 버튼이 모두 보이고 닫기와 겹치지 않도록 조정했다. ‘지우기’ 줄바꿈 때문에 마지막 줄만 커지는 오류도 수정했다.
- 숫자 버튼은 22~24px, 최소 50~54px로 키웠다. 공 퍼즐은 길 칸과 친구 이름을 키우고 연결망·지도·조각의 작은 표시도 다듬었다.
- 440px보다 좁은 가로 창에서는 협동 숫자판을 한 열로 배치하여 가로 잘림을 방지한다.

### 검증

87개 자동 검사, TypeScript·프로덕션 빌드를 통과했다. 로컬 568×320에서 교실 스스로·25분·협동을 처음부터 마지막 탈출까지 진행해 80점으로 완료했다. 긴 노트의 닫기와 퍼즐 복귀 위치, 메모·숫자판·연결망의 실제 글자 크기, 전체 페이지 스크롤, 숫자판 버튼 크기·화면 안 노출·닫기 겹침을 확인했다.

공개 배포 및 667×375·844×390 점검 결과는 워크스페이스 Escape-Class-phone-landscape의 검증보고서와 JSON을 참고한다. 브라우저 화면 크기와 UI 조작을 통한 검증이며 실제 휴대폰·태블릿 터치나 하드웨어 성능 검증은 아니다. 긴 퍼즐·노트에는 세로 스크롤이 남아 있다.

## 1.4.6 · 초등학생 관점 사용성 재검토

### 범위

공개 1.4.5를 실제 UI 조작으로 처음부터 80점 탈출까지 진행한 뒤, 초등학생이 다음 행동을 찾기 어렵다고 판단한 고도화 기능을 다듬었다. 실제 학생 관찰이나 실기기 시험 결과가 아닌 개발자의 사용성 점검이다. 색상·글꼴·3D 공간·게임 규칙·점수·저장 형식은 유지한다.

## 1.4.4 · 전체화면 전환 후 교실 로딩 멈춤 수정

### 원인과 수정

메뉴를 열 때 render()가 기존 sceneHost를 분리한 뒤 mountScene()이 모달 상태에서 조기 반환했다. 메뉴 뒤에는 새 로딩 문구만 남았다. 메뉴의 전체화면 동작도 모달을 닫지 않았으며 전체화면/가시성 변경은 이미 만들어진 장면의 크기만 조정하거나 상태만 갱신했으므로 지연된 최초 로딩을 다시 시작하지 못했다.

- 기존 3D 호스트를 먼저 화면에 재연결한 후 모달·일시정지에 따라 렌더링을 멈춘다. 메뉴 뒤에 로딩 문구로 바뀌지 않는다.
- 메뉴에서 전체화면 버튼을 누르면 메뉴를 동기적으로 닫고 그 클릭의 사용자 활성화를 유지하여 전체화면을 요청한다.
- 전체화면 상태 확정과 visibilitychange에서 mountScene()을 다시 호출한다. 최초 로딩이 일시적으로 보류된 경우에도 다시 시작한다.
- 보이는 활성 3D 화면에서 준비가 12초 안에 끝나지 않으면 기존 그림 교실 복구 경로로 이어간다. 모달·세로 안내·숨김·다른 화면에서는 이 제한을 취소하며 진행 기록을 보존한다.

### 검증 범위

자동 검사 80개, TypeScript와 프로덕션 빌드를 통과했다. 로컬 브라우저에서 메뉴 뒤 캔버스 유지, 전체화면 해제/재진입, 세로·가로 복귀, 좌우 보기, 게시판 선택, 퍼즐 화면의 전체화면 및 교실 복귀를 확인했다. 공개 배포 검증 결과와 화면 증거는 별도 산출물에 기록한다. 실제 휴대폰의 하드웨어 FPS를 측정한 검증은 아니다.

## 1.4.3 · 가로 안내 우선 시작과 모바일 렌더링 경량화

### 시작 흐름

휴대폰 세로 화면에서 게임 시작을 누르면 가로 회전 안내만 표시한다. 이때 활동 시간은 시작하지 않으며 3D 캔버스·장면을 생성하지 않는다. 직접 가로로 돌리면 자동으로 게임을 시작한다. 세로로 계속하기/닫기 버튼으로 안내를 건너뛰는 경로는 제거했다. 화면 회전 잠금을 끄는 안내와 시작 화면으로 돌아가기는 제공한다.

진행 도중 세로로 돌아와도 안내가 먼저 표시되고 그리기·활동 시간은 멈춘다. 다시 가로로 돌리면 기존 진행을 이어간다. 저장 기록을 새로고침해 복원한 경우에는 기존 일시정지/이어하기 정책을 유지한다. 가로 상태나 PC에서는 시작 버튼으로 바로 플레이한다.

휴대폰 크기의 세로 창과 터치 태블릿의 세로 화면에 적용한다. 브라우저에서 기기의 실제 방향을 강제로 돌리는 기능은 아니다.

### 버벅임 완화

- 정지 장면 재그리기를 초당 30회에서 4회로 줄여 빈 버퍼 복구는 유지하면서 대기 부하를 낮춤.
- 모바일의 이동·입력 그리기는 최대 30fps로 제한. 연속 입력도 프레임 예산 안에서 합쳐 처리.
- 모바일 내부 렌더 픽셀은 최대 약 50만, PC는 약 150만으로 제한. 글씨·버튼은 HTML 해상도를 유지.
- 모바일 실시간 그림자를 끄고 색상·광원·모서리 다듬기는 유지.
- 여러 바닥 나무선은 하나의 인스턴스 그룹으로 그려 반복 호출과 지오메트리 할당을 줄임.
- 움직임·상태·화면 크기가 바뀔 때 이름표 위치를 갱신하고 정지 상태에서 매 프레임 DOM 측정을 반복하지 않음.
- 가로 준비·로딩·다른 창·대화상자·퍼즐 패널에서는 새 3D 장면 생성을 미루고 그리기를 중단.

### 검사

자동 검사 80개와 TypeScript·프로덕션 빌드 통과. 브라우저에서 세로 시작 시 캔버스 0개, 안내 중 새로고침, 가로 회전 뒤 00:00 자동 시작을 확인했다. 협동 포함 교실 필수 퍼즐·최종 지도·열쇠·탈출을 완료했다. 렌더링 버퍼 복구와 프레임 제한/정지·재개 검사를 유지한다.

실제 휴대폰에서 FPS를 측정한 결과와는 구분한다. 구체적인 렌더링 예산과 시작 흐름을 개선했으며 실제 기기의 체감 성능은 기종·브라우저에 따라 다를 수 있다. 공개 Pages 검증 증거는 워크스페이스 `outputs/Escape-Class-landscape-start`에 보관한다.

디자인의 팔레트·글꼴·조작 버튼, 기존 저장·점수·공식 결과 형식은 유지한다.

## 1.4.2 · 모바일 시작 시 빈 교실 복구

증상: 게임 시작 후 이름표·이동 버튼은 보이지만 3D 교실이 배경색만 남는 화면.

개발 검사에서 이전 1.4.1 장면의 WebGL 버퍼를 비우면 같은 빈 화면이 남는 것을 재현했다. 기존 방식은 이동이나 입력이 없을 때 프레임 갱신을 중단했기 때문에 모바일 브라우저가 버퍼를 초기화·폐기한 뒤 다시 그릴 기회가 없었다. 사용자 실물 기기의 내부 로그를 확보한 것은 아니므로 그 기기의 발생 경로가 이 한 가지라고 단정하지 않는다.

수정:

- 활성·표시 중인 3D 장면은 정지 상태에서도 30fps로 다시 그린다. 이동·제스처는 더 자주 갱신할 수 있다.
- 일시정지·패널·대화상자·숨긴 탭·분리된 장면에서는 반복 그리기를 중단한다.
- 같은 크기의 canvas.width/height 재할당을 피한다. Three.js의 setSize는 같은 값에서도 버퍼를 초기화하므로 불필요한 호출을 줄였다.
- 전체화면·방향·창·visualViewport 변경 시 크기와 장면을 다시 확인한다.
- 렌더링 예외·셰이더 오류·GPU 컨텍스트 손실을 처리하고 기존 진행 보존형 그림 교실 전환으로 연결한다.
- 반복 렌더링 비용을 줄이기 위해 정적인 그림자 지도는 재사용하고 장치가 움직일 때 갱신한다.

검증:

- 기존 검사 70개 + 프레임 복구·중단·재개·오류 처리 검사 6개 = 76개 통과.
- 개발 전용 `tests/scene-recovery.html`: 활성 버퍼 초기화 후 교실 자동 재표시, GPU 연결 손실 처리 확인.
- 개발 전용 `tests/app-recovery.html`: 실제 앱에서 세로 시작·가로 전환, 첫 퍼즐 이후 GPU 장애 → 16점·진행 유지 → 그림 교실에서 80점 탈출 확인.
- 개발 검사 HTML은 Vite 개발 서버용이며 프로덕션 빌드 대상에 포함하지 않는다.
- 공개 배포·회전·메뉴/퍼즐 검증 증거는 워크스페이스 `outputs/Escape-Class-render-fix`에 보관한다. 실물 휴대폰 시험과 브라우저 화면 크기/장애 주입 시험은 구분한다.

게임 디자인·점수 판정·공식 결과 형식과 기존 진행 저장 키는 유지했다.

## 1.4.1 · 넓은 3D 탐색 화면

작은 가로 화면에서 제목·목표 안내·오른쪽 목적지·하단 아이템 칸이 교실을 압박하던 배치를 변경했다. 교실 색상·글꼴·버튼 모양을 유지했다.

- 3D 캔버스를 현재 화면의 전체 너비·높이에 배치하고 목표 한 줄·점수·일시정지를 상단에 띄운다.
- 오른쪽 목적지 세 버튼은 이동 메뉴로 통합했다. 가운데 복귀와 바닥 발자국 이동을 유지한다.

### 수업에서 쓰기

새 게임 또는 수업 안내에서 학년·시간·협동·이야기를 정한다. 새 게임부터 적용되며 진행 중 설정은 바뀌지 않는다. 기본 공식 규칙 버튼은 스스로·25분·협동 해제·요청형 힌트·EP.01로 돌린다. 실제 공식 결과는 원래 등록 학교·회차 등 조건을 모두 충족해야 한다.

모둠 자리 1~4번을 먼저 정하고 게임 상단 역할 버튼으로 확인한다. 도구함 앞에서 관찰 친구는 순서를, 읽기 친구는 숫자 사전을 설명한다. 기기 한 대에서는 카드를 번갈아 보며, 역할 카드 인쇄로 정보를 나누어 가질 수도 있다.

### 저장과 복구

기존 `classroom-escape:<배포 경로>:progress:v1`의 형식을 유지한다. 화면·수업 정보만 같은 이름 뒤 `:experience:v1`에 보조 저장하며 정확히 같은 진행 기록일 때만 복원한다. 기존 저장에는 협동 잠금을 추가하지 않는다. 활동 기록 삭제는 이 앱의 진행 키와 보조 키만 지운다.

Web Locks가 있는 브라우저에서 한 탭만 기록한다. 나머지 탭은 기록 보호 안내를 보여 준다. 다른 탭을 닫고 다시 확인하면 최신 저장을 읽어 이어간다. Web Locks가 없는 환경은 저장값 변경 감지로 최신 진행의 덮어쓰기를 막으며 완전한 원자적 다중 탭 소유권 보장은 하지 않는다. 저장이 차단되면 원래처럼 저장 경고와 함께 메모리에서 게임을 진행한다.

GitHub Pages 배포 결과와 공개 주소의 자산 일치·공개 게임 검증은 워크스페이스 산출물 `Escape-Class-upgrade-review`의 배포 증거를 참고한다. 수업 시간 적합성과 실제 학생 이해도는 교사·학생 수업 시험으로 확인해야 한다.
