# 공식 회차와 학교 결과 운영

이 앱은 정적 파일을 읽습니다. 학생 결과를 받는 서버와 자동 접수 API는 없습니다. 실제 학교 ID·이름과 회차 ID는 운영자가 결정합니다. 테스트의 `FIXTURE-*` 학교를 운영 데이터로 복사하지 마세요.

## 회차를 열기 전

1. 공식 도전 전에 학교 대표 모둠을 정하고 그 모둠의 완료 결과 한 건을 제출하는 규칙을 안내합니다.
2. 학생 수, 접속 수, 재도전 수를 점수로 사용하지 않습니다.
3. `public/data/schools.json`에 실제 승인된 학교만 추가합니다. 배열의 각 행은 `schoolId`, `name` 두 필드만 사용합니다. ID는 비어 있지 않은 중복 없는 내부 문자열이며 공식 교육행정기관 코드라고 주장하지 않습니다.
4. 학교 자유 입력이나 학생별 정보를 추가하지 않습니다. 학교 선택은 소속 인증이 아닙니다.

## 회차 개설

`public/data/game-config.json`의 `schemaVersion: 1`, `episodeId: "ep01"`, `difficultyId: "standard"`, `contentVersion: "ep01-1.0.0"`을 유지하고, `activeRound`를 다음 필드를 갖춘 객체로 바꿉니다.

| 필드               | 값                                                |
| ------------------ | ------------------------------------------------- |
| `roundId`          | 운영자가 정한 실제 회차 ID; 비어 있지 않은 문자열 |
| `label`            | 학생·교사에게 표시할 실제 회차 이름               |
| `acceptingResults` | 결과 접수 중이면 `true`                           |

`public/data/rankings.json`의 회차도 같은 실제 ID로 맞추고 새 회차의 `records: []`, `updatedAt: null`을 사용합니다. 새 회차에 이전 순위를 자동 복사하지 않습니다. 변경 후 정적 빌드와 Pages 배포를 진행합니다.

앱이 지원하는 콘텐츠 버전은 현재 `ep01-1.0.0`입니다. 설정 파일의 버전만 임의로 올리지 마세요. 콘텐츠를 개정할 때는 코드의 지원 버전, 저장 호환 정책, 판정·파일 검증을 함께 갱신하고 다시 확인해야 합니다.

## 학생·교사의 결과 저장

1. 현재 접수 회차가 배포된 뒤 **새 게임**을 시작하고 등록 학교를 선택합니다. 새 게임의 기본값(쉬움 · 차근차근)은 연습 모드이므로, 시작 화면의 ‘더 자세히’에서 **기본 공식 규칙으로 맞추기**를 눌러 기본 · 스스로 난이도로 시작해야 공식 결과를 낼 수 있습니다. 시작 화면의 학교 선택 안내에도 현재 설정이 연습인지 표시됩니다.
2. 모든 필수 퍼즐, 마지막 지도 조합, 화분의 열쇠 획득, 출구 사용까지 완료합니다.
3. 결과 화면의 공식 결과 다운로드를 누릅니다. 이 순간 현재 설정을 다시 읽습니다.
4. 다운로드 파일을 교사가 지정한 전달 경로로 운영자에게 보냅니다. 앱이 자동 제출하거나 메시지를 보내지 않습니다.

회차 없음, 접수 종료, 설정 읽기 실패, 등록 학교 없음, 탈출 전, 저장한 회차·버전과 현재 설정 불일치 중 하나라도 해당하면 공식 내보내기가 차단됩니다. 이전 회차 저장의 회차 ID를 새 회차로 바꾸지 않습니다. 호환되는 이전 회차 활동은 연습으로 이어갈 수 있습니다.

결과 파일은 `schemaVersion`, `recordType`, `episodeId`, `roundId`, `difficultyId`, `contentVersion`, `schoolId`, `solvedPuzzleIds`, `foundBonusIds`, `escaped`만 허용합니다. 점수를 입력받지 않고 P1~P5 ×16 + 보너스 ×5로 재계산합니다. 이름·활동 시각·기기 ID·성찰·힌트 이력을 파일이나 파일명에 넣지 않습니다.

## 로컬 집계

1. 운영자가 대표 모둠과 결과의 적절성을 확인합니다. 파일 검사는 실제 플레이를 증명하지 않습니다.
2. `#/tools/results`를 엽니다. 유효한 현재 설정과 접수 중인 회차가 필요합니다.
3. 현재 회차의 기존 공개 순위 파일이 있다면 먼저 불러옵니다. 그 뒤 결과 파일들을 불러옵니다. 두 종류를 동시에 선택해도 검증은 별도 스키마로 수행됩니다.
4. 한 번에 최대 100개, 파일마다 100KB(102,400바이트)까지 읽습니다. 오류 파일은 반영하지 않고 이유를 표시합니다.
5. 완전히 같은 결과는 한 건으로 유지합니다. 같은 학교의 다른 점수는 **기존 유지** 또는 **새 결과 교체**를 선택해야 합니다. 여러 후보가 있으면 파일을 읽은 순서의 명시적 교체 선택이 적용됩니다.
6. 미결 충돌이 없으면 `rankings.json 다운로드`를 누릅니다. 생성 직전 설정을 다시 읽으며, 설정이 바뀌면 파일들을 다시 검증하도록 집계를 초기화합니다.
7. 다운로드 파일의 학교·점수·회차·게시본 생성일을 확인하고 저장소의 `public/data/rankings.json`에 반영합니다. 앱에는 원격 쓰기 기능이 없습니다.
8. 저장소 절차에 따라 빌드·배포하고 실제 공개 순위를 확인합니다.

공개 순위 행에는 `schoolId`, `score`, `bonusCount`, `escaped`만 허용합니다. `bonusCount`는 0~4 정수, `score`는 `80 + 5 × bonusCount`, `escaped`는 `true`여야 합니다. 학교 중복과 알 수 없는 필드를 거부합니다. 정상 순위 행에 결과 파일용 퍼즐 ID를 요구하지 않습니다.

점수 내림차순으로 표시하며 100·95·95·90점은 1·2·2·4위입니다. 이름순 정렬은 동점 행의 화면 배치에만 사용합니다. 시간과 힌트는 순위에 영향을 주지 않습니다.

## 접수 종료와 지난 회차

마지막 순위 게시를 완료한 뒤 같은 `activeRound` 객체의 `acceptingResults`를 `false`로 바꿔 배포합니다. 마지막 순위는 해당 회차와 **회차 종료** 표시로 계속 조회할 수 있습니다. 이때 내보내기·집계·순위 생성은 사용할 수 없습니다.

`activeRound: null`로 바꿔 연습으로 돌릴 수도 있습니다. 마지막 순위 파일이 남아 있다면 **지난 회차 · 종료**로 표시합니다. 기본 초기 파일처럼 `roundId: null`인 순위 파일은 반드시 빈 `records`를 가져야 합니다.

다른 회차를 새로 열 때 지난 게시본은 저장소 이력이나 운영자의 별도 보관본으로 보관한 뒤 현재 순위 파일을 새 회차의 빈 파일로 교체합니다. 현재 앱에는 여러 과거 회차를 선택하는 보관함 UI가 없습니다.
