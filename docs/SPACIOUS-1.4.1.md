# 1.4.1 넓은 3D 탐색 화면

작은 가로 화면에서 제목·목표 안내·오른쪽 목적지·하단 아이템 칸이 교실을 압박하던 배치를 변경했다. 교실 색상·글꼴·버튼 모양을 유지했다.

- 3D 캔버스를 현재 화면의 전체 너비·높이에 배치하고 목표 한 줄·점수·일시정지를 상단에 띄운다.
- 오른쪽 목적지 세 버튼은 이동 메뉴로 통합했다. 가운데 복귀와 바닥 발자국 이동을 유지한다.
- 좌우 보기는 양쪽 아래 원형 버튼으로 배치한다. 주요 터치 영역은 48px 이상이다.
- 큰 아이템 칸을 가방과 도구 개수로 대체하고, 선택한 도구는 별도 짧은 안내와 색상으로 표시한다.
- 단서 노트·물건 목록·모둠 역할·설정·전체화면·그림 교실 전환은 메뉴에서 연다.
- 화면의 물건 이름은 다음 목표와 가까운 순서로 우선 표시한다. 작은 화면은 최대 3개, 큰 화면은 최대 4개이며, 물건 목록과 물건 직접 선택을 유지한다.
- 이름표는 상단 위치 안내·하단 메뉴·선택한 도구 안내를 피한다. 퍼즐을 펼치는 화면은 기존 글씨·버튼 크기와 스크롤을 유지한다.
- 탐색용 메뉴에서 키보드 초점을 복원하며 도구 선택 직후 저장한다. 이동 메뉴는 기존 안전 통로 경로를 재사용한다.

검증: 기존 로직 70개, TypeScript·프로덕션 빌드, 교실 스스로·25분 협동 포함 전체 탈출 80점. 가방 선택·해제·새로고침 복원, 창가 이동·가운데 복귀, 모둠 역할과 2D/3D 전환을 브라우저에서 확인했다.

로컬 화면 크기 시험에서 기본 조작 UI가 덮지 않는 면적: 568×320 75.0%, 844×390 80.7%, 1024×768 91.9%, 1280×591 91.6%. 캔버스는 화면 전체를 채운다. 비율은 기본 HUD·메뉴 버튼·위치 안내의 사각형 합집합을 제외한 계산이며, 이름표·가방 선택 안내·열린 대화상자는 별도 상태다. 실물 휴대폰·태블릿 시험을 의미하지 않는다.

화면 크기별 측정·캡처·공개 Pages 배포 증거는 워크스페이스 `outputs/Escape-Class-spacious-review`에 보관한다. 진행 저장 형식과 게임 판정·점수·공식 결과 파일은 변경하지 않았다.
